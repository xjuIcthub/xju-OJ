# Frontend package-manager bridge contract

## Phase 1 bridge

- Node is locked to `24.19.0` by `frontend/.nvmrc` and the frontend image uses the verified `node:24.19.0-bookworm-slim` manifest digest from the modernization version lock.
- `pnpm@11.22.0` is the package-manager source of truth for the bridge. `frontend/pnpm-lock.yaml` is generated from the existing `yarn.lock`; `yarn.lock` and the legacy Webpack build remain rollback assets until Phase 3.
- `jquery@2.2.4` and `codemirror@5.65.16` are explicit top-level dependencies because application source imports them directly.
- `tar-simditor@3.0.5` retains its existing pinned Git subdependencies from `yarn.lock`. `frontend/.npmrc` and `frontend/pnpm-workspace.yaml` make this legacy exception explicit; it is not a new unreviewed source dependency and is deferred to the Phase 3 editor migration.
- pnpm build-script approval is limited to the legacy packages recorded in `frontend/pnpm-workspace.yaml`; no production secret or runtime data is part of the install context.

## Build and rollback

- `pnpm install --frozen-lockfile`, `pnpm run lint`, and `pnpm run build` are the bridge checks.
- `pnpm run build` uses the Vite dual-entry bridge. `pnpm run build:legacy` retains the previous Webpack path.
- Vite emits `dist/index.html` and `dist/admin/index.html`; runtime configuration is generated by the Nginx entrypoint and never contains secrets.
- If the bridge fails, remove the Vite/package-manager bridge files and use the retained Yarn/Webpack image; no backend, database, Redis, or Judge rollback is required.
